- `viewport: { themeColor: '#f59e0b', width: 'device-width', initialScale: 1, maximumScale: 1 }`.
- Apple touch icon linked in `icons.apple`.

**Service worker** (`frontend/public/sw.js`, registered by
`components/ServiceWorkerRegistration.tsx` on mount):
- Cache name: `arc-v1` — hardcoded, manually bumped.
- Precache: `/`, `/manifest.json`, and the three icons.
- Fetch strategy: `/api/*` bypass, `/_next/static/*` cache-first, **all
  other GETs including HTML: network-first with cache-fallback** — every
  HTML response is written to the SW cache. **This is the problem — §2.**

**Registration**: `navigator.serviceWorker.register('/sw.js')` from a
`useEffect` in `ServiceWorkerRegistration`. No `updatefound` listener, no
user-facing "new version available" prompt.

**Serving**: `/sw.js` and `/manifest.json` both return `cache-control:
public, max-age=0` at the edge — browsers always revalidate the SW script,
so a bumped SW gets picked up on next visit. Good.

## 2. SW vs the 60s revalidate window — finding, not fixed

**Problem**: the "network-first with cache-fallback for pages" branch calls
`caches.put(request, clone)` on every HTML response. That means:

- Every page an authed user visited lands in `arc-v1`, keyed by URL only —
  no partitioning by cookie or session state.
- Online users still get fresh content (network wins when it works), so
  the 60s ISR revalidate isn't defeated in the normal case.
- But if the network then fails — flaky wifi, backend outage, genuine
  offline — the SW serves the cached HTML from potentially weeks earlier.
  **A user who logged out could see their previously-authed HTML from
  cache.** Small: same device, no cross-user leak, but a real
  "logged-out but still see my old private view" bug.
- Cross-deploy drift: `CACHE_NAME` is hardcoded `'arc-v1'`. Old caches are
  cleared only on `activate` when the name changes. Between manual bumps,
  the cache grows unbounded with per-page HTML entries.

**Fix (queued in TODO, not applied here)**: rewrite sw.js as a pure
static-asset accelerator — no HTML in the cache at all, precache only
`/manifest.json` + icons, bump `CACHE_NAME` so `activate()` cleans up
`arc-v1`. Full diagnosis + before/after snippets in TODO.md § *SW: stop
caching HTML*.

## 3. Auth × PWA — same finding

The auth-cache-bypass invariant that the server-side ISR guarantees (SSR
never reads cookies → cannot cache a personalized page) is **broken by the
SW's HTML caching**. The SW writes to cache after receiving the response,
independent of what the server did. Fix is the same as §2.

## 4. Installed-app session isolation (the SoC pattern)

`display: standalone` (manifest.json) + `appleWebApp.capable: true`
(layout.tsx) are both set. On iOS, that means "Add to Home Screen" launches
arc-codex in a standalone WebView.

**iOS storage-partition behavior**: historically (pre-iOS 15) the standalone
webapp ran in a **separate storage partition from Safari** — cookies set in
Safari did not carry over to the installed app. This is the shape the SoC
anonymous-pass incident hit. Since iOS 14, WKWebView-based standalone apps
have shared credentials with Safari in most flows, but edge cases persist
(private-mode Safari, some cross-domain OAuth redirects, iOS version
skew).

**Concretely for arc-codex**: a user who authenticates via Google OAuth in
Safari and then launches the installed home-screen app may or may not be
signed in there on any given iOS version. That's user-facing confusing but
not a security bug — the installed app cannot see the browser's session
without an explicit sign-in of its own.

**Not changed in this pass** — no fix that fits the <5-line rule; queued
in TODO as an accept-or-mitigate decision, not a code change.

## 5. Conformance pass

- **Manifest**: all required fields present; icons are 192 + 512 with
  `purpose: 'any maskable'`; `start_url` and `display` set; served as
  `application/json`. Valid.
- **Icons**: all three URLs return 200. Sizes match manifest declarations.
- **Offline behavior (today)**: SW returns cached HTML for previously
  visited pages. Post-fix: browser default "no internet" for HTML,
  precached icons and static chunks still render. Both acceptable for a
  news feed; no dedicated offline.html exists or is proposed.
- **Lighthouse**: not run — Chrome-driver is available via the
  `claude-in-chrome` skill; queued as a nice-to-have baseline in TODO.

## Summary

- Manifest + icons + meta: **correct**.
- SW static-asset caching (`/_next/static/*`): **correct**.
- SW HTML caching: **broken by design** for the ISR + auth model this
  codebase now runs. Fix diagnosed, deferred (see TODO.md).
- iOS installed-app session parity: **noted risk** (SoC pattern), no
  short fix.
